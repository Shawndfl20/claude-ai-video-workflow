# 制作流程与标准

从选题到上传，一条视频的完整流程。命令见 [README](../README.md)，工具和函数见 [kit/README.md](../kit/README.md)。

频道设定（语言、观众、形式、配音方式、用语）因人而异，写在项目根目录的 `channel.md`，见 [AGENTS.md](../AGENTS.md)。本文只写不随频道变化的方法和标准。

**思路：** 视频全部由代码和 AI 生成，不和素材剪辑、真人出镜的频道比同一种东西。要赢在三点：

1. **有趣：** 选题和讲法要让人看完，看完还想订阅。实用教程也要找故事和比喻。
2. **画面：** 镜头和画面是代码视频的主场。每支视频都可以换风格，不拘泥于模板或示例视频。
3. **从零讲起：** 默认观众是新手，最基础的概念也讲清楚。

## 1. 选题

### 选题组合

| 类别 | 形式 | 流量来源与作用 |
| --- | --- | --- |
| 教程、入门、"怎么做" | 横屏长视频 | 搜索。新频道也能被搜到，发布后长期带量 |
| 时效内容（新闻、分析、预测） | 横屏长视频 | 推荐和订阅。时效短，有基础观众后再放量 |
| 机制讲解、长视频精华 | Shorts | 推荐。起量、拉新，给长视频导流 |

**冷启动先做搜索型，再做时效型。** 零订阅的频道发时效内容基本没人看；教程、入门靠搜索进来，长期有流量。Shorts 同步发，选题紧贴频道主题，让推荐把频道推给对的人群；泛科普冷知识只当开篇，不当主线。

### 每条视频的要求

- **一个能讲清的问题，而不是清单。** "为什么黄金成了钱"可以一轮轮推出原因，"黄金的 5 个冷知识"看完就忘。
- **讲解类找一个能贯穿全片的比喻或游戏结构。** 它要能同时管住多个变量：黄金那条用"淘汰赛"，每淘汰一轮就讲一个条件；券商那条用"找代购 / 自己飞 / 机票钱"。只够说一句话的比喻不用。
- **先写一句话主线：** 观众看完能带走什么。
- **从零讲起：** 每个术语第一次出现时用一句白话解释，并配一张术语卡。
- **结尾给订阅的理由：** 预告下一集要解决的具体问题，而不是只说"记得订阅"。
- **用观众本地的说法：** 按 `channel.md` 的用语要求写，例如给台湾观众用"停損""槓桿"，不是简中词汇转繁体。
- **题材规则看 `channel.md`：** 例如财经类的免责声明、预测写成"条件 + 情景"并事后对账。

## 2. 脚本

- **开头 2 秒给钩子：** 一个反直觉的事实或画面（一万个比特币换两张披萨；118 种元素只选中一个）。不要从背景讲起。
- **顺序：** 先结论再机制，先"你以为的"再"实际上"。每段只讲一件事。
- **结尾回到开头，** Shorts 能循环播放。可以用一句总结收束，不用文字卡片堆总结。
- **数字是用来制造反差的。** 每个数字要么配一个可比的对象（22 米的立方体旁边放一栋 7 层楼），要么删掉；口径有分歧的数字不写。
- **克制：** 不用夸张的情绪词，让事实和对比本身制造反差。
- **多音字和易混词换掉：** 例如"笔"和"币"读起来一样，就别让它们在同一个语境里出现。
- **时长：** 按讲清一个问题所需，不凑时长。Shorts 上限 180 秒，要留 1 秒余量；看留存数据再调整这个频道的合适长度。

## 3. 事实核对

- 每条事实性说法要有可查的出处，写进本片 README 的"事实核对"表。
- 学界有争议的说法用保守措辞（"much of""likely"），不给比例。
- 会随时间变化的数字（价格、存量）只说量级，或者写上时点。

## 4. 配音与读音核对

```bash
node kit/tools/make.mjs videos/<name> --draft
```

- 按 `channel.md` 选配音，写进 `video.json` 的 `voice`：`minimax` 可设 `voiceName`（voice_id）、`emotion`、`languageBoost`（语种提示，默认 Chinese）、`speed`；`hume` 可设 `voiceName`；没有密钥时用 `kokoro` 出草稿。
- 读音核对用离线识别模型（`scripts/fetch-models.sh`）；繁体台词会先转成简体再和识别结果比对。

### 用户自己生成的旁白

用户想用 API 没有的音色时（例如在配音网站的网页版生成），流程是：

1. **导出台词：** 台词定稿后，把各句 `t` 按顺序导出成纯文本给用户，每句一行，不混入场景名和画面说明。
2. **生成：** 用户在网页上生成并下载音频。每句以句号等结尾，让句与句之间有停顿；台词太长可以分几段生成，按顺序命名。
3. **导入：** 音频放进本片文件夹，`video.json` 写 `"voice": {"provider": "file", "files": ["narration-1.mp3", "narration-2.mp3"]}`，再运行 `make.mjs --draft`。`import-voice.py` 在停顿处把旁白切成逐句时间轴；装了识别模型时按识别结果对齐台词，切句最准，没装时只按句长，句间停顿短就可能切偏。
4. **核对：** 看导入时打印的每句长度，标 `!` 的句子要听；再看读音核对的结果。旁白自带停顿，台词的 `hold` 不再生效。
5. **改台词就重新生成受影响的段落并重新导入，** 不要拿旧时间轴套新音频。
- 读音核对的结果要逐条看：同音字（它/他）、人名拼写的差异不算错；数字念错、漏字、读错多音字要改台词或加读音表（`video.json` 的 `voice.pron`，仅 MiniMax 支持）。

## 5. 画面

页面约定（工具依赖这几条）：

- **只由时间决定画面：** `render(t)` 只由 `t` 决定画面，不用随机数、系统时间、定时器、CSS 动画。
- **元素只建一次：** 加载时建好所有元素，`render(t)` 里只改透明度、位置和变换。
- **节拍挂在词上：** 每个节拍都写成 `W(句号, "词")`，改台词或换配音后自动对齐，不写死秒数。
- **音效节拍在建页面时登记：** 用 `cue(t, kind)` 在加载时登记，不要在 `render` 里调用。

风格与镜头：

- **每支视频先定风格再画：** 读完脚本，给用户 3 种候选风格（长什么样、为什么适合这条、代价），各出几秒样片，用户选定后全片只用这一种。例如微缩立体世界、纸片拼贴、游戏界面、蓝图、复古电视等；不必沿用模板的深色舞台，也不照搬示例视频。
- **用镜头讲故事：** 一个连续的世界加推拉摇移、跟随、转场，胜过一张张静态分屏。比喻要变成可以"走进去"的场景。
- **数据做成实物：** 费用是一叠硬币、门槛是一道门、进度是一条路，少用干巴巴的表格。
- **记录与收敛：** 本片 README 写明风格和镜头手法；之后按播放和留存数据，把好的风格沉淀进 `kit/`。

好看、好懂的标准：

- **一刻一个焦点。** 旁白讲到什么，画面就出现什么；讲完的东西退场或变暗。
  - 动手前先列一张"每一拍的焦点"表；每个元素写明从哪个词出现、到哪个词退场，不写"留到场景结束"。
  - 讲完的东西离场，不是变淡留着：半透明的残影一样干扰视线。只有这句话本身在比较两样东西时，两样才同时在画面上；话题转到其中一边，另一边就走。
  - 不放常驻元素：角色名牌、章节标题、装饰字（TUTORIAL、LOADING 之类）都算干扰。章节名只在进章节时出现一两秒。
  - 同一句里的变化，在同一个对象上原地完成（例如流程图里去掉一环、柱子换场景时标题跟着换），不再另起一张卡；能画出机制的，不用文字卡复述台词。
  - 镜头跟着台词里的主语走：讲到哪一方，镜头就对准哪一方，在那个词上切换。
  - 数据面板占画面正中，场景同时退场；不和无关场景各占半边。
  - 审片用 `contact.mjs --mode beats` 看每句的开始、中间、结束三帧：句末那一帧最容易堆满。
- **同一个对象原地变化，** 不在旁边再画一个新的。
- **数字一次到位。** 不做连续跳动的计数器，需要变化时分档跳。
- **画面文字只用来指认对象、标数据，** 不复述字幕。每段文字至少停留 1.5 秒（检查会拦）。
- **字幕：** 样式跟着画面风格选：影视字幕（白字深色描边，无底框）或胶囊字幕（有底框），都是一屏一行。繁体内容用 `buildShell({ glyphs: "TC" })` 换繁体字形。字幕区在画面下部：竖屏字幕只放一行、每屏最多 14 个字（`makeChunks({ maxChars: 14 })`），从 y 1450 起（影视字幕 1490），底边约 1570，避开 Shorts 底部的标题、频道名和右侧按钮，主体画面放在 y 1430 以上；横屏字幕底边离画面下沿 120px（`kit` 默认值），避开播放器的进度条和按钮。横屏字幕只放一行，每屏最多 16 个字（`makeChunks({ maxChars: 16 })`，与 Netflix 繁中字幕每行 16 字一致），胶囊字幕 64px、影视字幕 72px：手机竖拿看横屏时画面只剩约 390px 宽，字数少才能用大字。
- **横屏内容安全区：** 画面文字和主体都放在 x 150–1770、y 130–797 以内，并以这个区域为中心布局。顶部留给播放器标题栏，左右是视线边缘，底部留给字幕。方框不要撑满画面，数据面板约占画面高度的六成以内。
- **手机上清晰优先：** 用平涂色块加清楚的描边，避免全屏半透明层、大范围模糊。

## 6. 检查与审片

`make.mjs` 会自动跑检查，硬性失败就停：

- 页面报错；
- 缺字形；
- 字幕溢出；
- 文字闪现不到 1.5 秒；
- 画面空白超过 0.5 秒；
- 时长超限；
- 视频规格不符。

警告（字太小、字太多、文字重叠、画面静止）要逐条判断；决定保留的，在本片 README 写明理由。

审片步骤：

1. 看拼板 `build/<name>-sheet.png`：构图、裁切、重叠；
2. 需要细看的帧，用 `kit/tools/frames.mjs` 出全尺寸截图；
3. 在手机上带声完整看一遍成片：节奏、转场、音画同步。拼板看不出这些。

## 7. 发布

- **标题：** 手机上大约显示 40 个字符，把反差放在前面。教程类把观众会搜的词放进标题（例如"美股开户""复委托"）。
- **描述：** 第一行重复视频里的钩子，然后列出看点，最后附来源名称；Shorts 加 `#Shorts`。
- **标签：** 主题词、问题式搜索词、相关概念，总长不超过 500 个字符。
- **题材需要免责声明时（见 `channel.md`），最多一句。**
- 成片和封面在 `build/`，直接上传，不入库。

## 8. 每条视频的 README

每条视频的文件夹里写一份 README，记录：

- 主线；
- 风格与镜头手法；
- 画面结构；
- 事实核对表；
- 配音提供方和花费；
- 读音核对结论；
- 保留的检查警告及理由。
